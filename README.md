# СППР клиники «Здоровье+»

Проект по курсовой работе Пинчука Д.В. Модуль лабораторной №2 реализует запись пациентов на приём к врачу и отмену записи с сохранением истории.

## Возможности

- Проверка активности пациента и врача.
- Запрет пересечений расписания как врача, так и пациента.
- Разрешение соседних интервалов без общего времени.
- Транзакционная запись приёма и события аудита.
- Отмена без удаления истории, повторная запись на освободившееся время.
- PHP-форма регистратора с CSRF-проверкой и экранированием вывода.

## Структура

`src/` – рабочий сервис PHP; `public/` – интерфейс; `sql/` – структура и обезличенные данные; `tests/` – четыре интеграционных сценария; `.github/workflows/` – автоматизация; `docs/` – документация и протокол GitFlow.

## Запуск

Требуются PHP 8.3 с pdo_mysql и MySQL 8.0. Создайте БД `zdorovye_plus`, импортируйте `sql/schema.sql` и `sql/seed.sql` в phpMyAdmin. В окружении задайте DB_HOST, DB_PORT, DB_NAME, DB_USER, DB_PASSWORD. Из корня запустите `php -S 127.0.0.1:8080 -t public` и откройте http://127.0.0.1:8080.

Модуль предназначен для локального запуска с обезличенными данными. Вход и разграничение пользователей веб-приложения в данный модуль не входят.

## Тестирование

Тесты используют отдельную БД, имя которой обязательно заканчивается на `_test`. Сначала импортируйте `sql/schema.sql`, затем выполните `php tests/run.php all`. Один сценарий: `php tests/run.php 1` (номера 1–4). Тестовые таблицы очищаются перед и после сценариев. Не используйте рабочую БД.

Actions запускает MySQL 8.0, PHP 8.3, проверку синтаксиса, четыре сценария и сохраняет JUnit-отчёты как `clinic-test-results`. События: push, pull_request и workflow_dispatch.

## GitFlow

`main` – выпуски, `develop` – разработка, `feature/appointments` – функция записи, `release/1.0.0` – подготовка выпуска, `hotfix/1.0.1` – исправление параметров сессии. Слияния оформляются Pull Request с сохранением merge-коммитов.
